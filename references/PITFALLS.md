# 致命坑全表（NWNEE 汉化）

每条：**现象 → 根因 → 正解**。叙事版见工作区根 `HANDOFF.md` §⑤。截至 2026-10-17 共 19 坑 + 环境坑。

---

## 🔴 坑 1：ERF V1.0 头字段读反
- **现象**：只枚举 52/255 资源，漏 `.ifo`/`.are`/`.git` → 游戏加载不了。
- **根因**：`LocalizedStringSize`(0x0C) 与 `EntryCount`(0x10) 读反。
- **正解**：0x08 LanguageCount / **0x0C LocalizedStringSize** / **0x10 EntryCount**；
  验真伪：`首资源 offset = ResOff + EntryCount×8`。

## 🔴 坑 2：GFF 回嵌 Index 区字节数 ≠ cnt×4
- **现象**：按 `cnt*4` 拷贝 → lio 算到文件外 → **游戏必崩**。
- **根因**：每个 struct/list 前还有 4B count 头，无法由 cnt 推算。
- **正解**：把 `[fio, 文件尾)` 整段原样保留，`新lio = 新fio + (原lio − 原fio)`。已固化进 `gff_reembed._assemble`。

## 🔴 坑 3：不要"按标准布局重写" ERF，改用 append-only
- **现象**：标准重写会丢 keylist 与 reslist 之间的等长结构数据（Act I 实测 −32,224B）。
- **正解**：`erf_pack.pack` v3 追加式——header/keylist/loc/未改资源字节全不动，被替换资源追加到文件尾。
- **验收铁律**：**空翻译重建体积必须与原版完全相等**。
- ⚠️ **反面提醒（2026-10-13 CEP 注入实测）**：追加式在**同一成品上反复重做**会累积膨胀 → 大规模重做必须从干净备份出发（如 `MOD/modules_bak_cep_20261013/`），不要在已膨胀成品上继续追加。

## 🔴 坑 4（最致命，曾让 Act I 全体 NPC 点不动）：GFF List 结构 data 不在 FieldData
- **现象**：点人没反应（dlg 的 `EntryList`/`RepliesList`/`StartingList` 均为 List，指飞）。
- **根因**：官方类型 `14=Struct`、`15=List`，data 不在 FieldData。旧 `OFFSET_TYPES` 误把 15 当 FieldData 块 → 每个 List 字段的 data 被改写成垃圾偏移。
- **正解**：`OFFSET_TYPES=(6,7,9,10,11,12,13)`；List/Struct 的 data 原样保留（尾部整段搬运）。
- **教训**：校验器**必须独立于被测实现**，不能复用被测代码的解析器（旧校验自证清白全过）。

## 🔴 坑 5：回嵌器 `reembed()` 第 3 参是【扁平】字典
- **现象**：`{"<field_idx>": "中文"}`；多包一层时 `rules.get(str(i))` 全部落空 → "替换 0 处"但体积照样变大。
- **正解**：**体积变化 ≠ 翻译生效**，必须看 `替换 N 处` 计数（报告里）。

## 🔴 坑 6（实锤）：type 10 CExoString 禁止翻译
- **现象**：两类引擎键被翻 → 脚本引用失配、NPC 点不动、说话动画匹配失效。
- **根因**：`gff_reembed._build_fd` 原 `if ft in (10,12)` 一视同仁。
  - `Tag` 是 `GetObjectByTag("BodyStorage")` 的查找键（死亡尸体处理、任务脚本直接失效）。
  - `Speaker` 是 dlg 里匹配说话人的 **Tag 键**（非显示文本），2207 处 100% 精确等于某 utc/git 的 Tag；翻掉后对不上；UI 显示的 NPC 名来自 utc 的 `FirstName`/`LastName`（LocString，**已翻**），翻 Speaker 零收益纯风险。
- **正解**：`_build_fd` 改为 `if ft == 12`（只翻 CExoLocString）。修后 `CExoString 变更 0`。

## 🔴 坑 7：`backfill.py` 报告只打印最后 6 行
- **现象**：stdout 只能看到末尾 2~3 个文件名，别拿它统计命中分布。
- **正解**：完整报告在 `<ch>/_backfill_report.txt`。

## 🔴 坑 8：`apply_nondlg.py` 末尾空行
- **现象**：内部标记（如 `inn`/`spot_trigger`）本该留空，却被丢掉 → 行数对不上。
- **根因**：原 `while lines and not lines[-1].strip(): lines.pop()` 会把"末尾有意留空"的行丢掉。
- **正解**：只丢掉"文件末尾换行"产生的那一个空元素（已改）。**译单行时末条若应留空，必须显式多写一个空行**。

## 🔴 坑 9（实锤）：提取器漏掉「strref 有效 + 内嵌英文 substring」整类
- **现象**：CEP/官方资源里大量条目 strref 指向 TLK（残留模板）+ 作者另写英文 substring，游戏显示 substring 不是 strref → 这一类必须译，原提取器整类漏掉（Act I 实测 1,109 条/820 唯一）。
- **正解**：**不要看 strref，只看 LocString 有没有非空 substring**。

## 🔴 坑 10：不能靠「strref 查官方中文 TLK」自动套译文
- **现象**：EE 汉化包 `dialog.tlk` 有 106,801 条中文，按 strref 能查到 815/820（99%），但抽查大量错配：
  `A Bed.`→`一块加工过的木头…`、`Bracksford Highway`→`<文字放这里>`、`Boots of the Swift Wind +2`→`日魂之靴+1`、`Cloth Dye, Beige`→`布匹染料，黑色`。
- **正解**：**TLK 只能当参考，不能自动套用**。标准物名可沿用官方译名，自创名一律手译。

## 🔴 坑 11：回嵌器按原文匹配时只看第一个 substring
- **现象**：BioWare 官方对话（英/德/法/意/西/波并存）顺序不定 → 整条漏翻。
- **正解**：`_pick_src()`：langid 0 非空优先 → 其次能命中词典的非空串 → 其次第一个非空串。

## 🔴 坑 12：同一句话有的带英文双引号、有的不带
- **现象**：`"I don't want..."` 与不带引号变体并存，精确原文匹配漏翻整条（Act I 22 唯一/101 次）。
- **正解**：`backfill.load_mapping()` 已自动为每个 key 补一个引号变体别名（不覆盖已有映射）。

## 🔴 坑 13（实锤）：抽取清单剥尾空格 → 整串精确匹配漏翻
- **现象**：`extract_nondlg.py` 生成清单时剥掉字符串尾空格，但 mod 实际 CExoLocString 子串常带尾空格（`...dye your armor. "` 是 61 字节、尾部有空格）→ 清单无尾空格键 ↔ 资源带尾空格子串对不上 → 整条漏翻。
- **正解**：译文映射构建时对所有不含尾空格的 key 自动生成 `s + ' '` 变体：
  ```python
  out = {}
  for s in remain:
      out[s] = T[s]
      if not s.endswith(' '):          # 尾空格容错
          out[s + ' '] = T[s]
  ```
- **经验**：凡"整串精确匹配"的回填，资源侧子串与清单侧键的空白差异必须显式对齐。

## 🔴 坑 14（老板当场纠）：译名必须以「译名表 + 已交付章节实文」为唯一基准
- **现象**：译 Pt3 时未先读 `译名表.md`，既漏主表定案（`Fairloch→菲尔洛克`、`Culdeny→卡尔德尼`），又把表内自相矛盾的写法（`埃达`/`撒旦纳斯`）照抄。
- **正解**：翻译前先读 `译名表.md`；每章译完/改名后跑 `_name_audit.py` 复验；表内定案与已交付实文冲突时**改表不改实文**；大批量改名先 `cp` 到 `backups/<日期>_<序号>_<事由>/`。

## 🔴 坑 15（2026-09-15 实锤，492 处）：作者复用官方 strref 当「万能描述槽」→ TLK 内容错配
- **现象**：Aielund 作者把 `14739`(官方=桌子描述)、`14576`(官方=书架)、`12460`(官方=黑龙描述) 当万能槽复用，内嵌了完全不同的自定义文本（雾气弥漫 307 处、吧台 80+、酒柜 16、飞龙 5…）。CExoLocString 的 StrRef 有效时，TLK 优先的客户端对飞龙按 Examine 会看到「黑龙」描述。
- **正解**：**重指 StrRef → 0xFFFFFFFF(-1)**，引擎即无条件显示内嵌译文。工具 `work/fix_strref_mismatch.py`（同尺寸 dword 原位补丁 + 官方签名白名单：内嵌=官方（真·书架）与空内嵌（官方默认对象）**不动**；dlg 零命中）。已修 7 成品共 492 处（act1 70 / act2 288 / act3 43 / Pt2 91），verify 全 PASS、体积不变。
- **⚠️ 铁律**：`backfill.py` 从原版重建 mod 会**还原旧 StrRef** → **每次 backfill 后必须重跑 `fix_strref_mismatch.py`**（先 `--dry-run` 核对数量）。
- **教训**：与坑 9/10 是一体三面——坑 9「strref 有效+内嵌要译」、坑 10「TLK 不能自动套」、坑 15「内嵌译完还得防 TLK 抢显示」。

## 🔴 坑 16（2026-09-15 实锤）：改译只改 cn 源、漏改 `*_filled.json` → 回填消费旧值
- **现象**：act4p3 暮光地名改了 `cn_are.txt`（源）但漏改 `nondlg_are_filled.json`（生成物）→ 重跑 backfill 后 area 名 11 处**仍旧值**入包（`verify` 全 PASS——它比对结构不比对内容对错）。
- **根因**：`backfill.py` 实际消费 `batch_*.json` / `nondlg_*_filled.json`，cn 源只经 apply 步骤才变成生成物。
- **正解**：改定案**双写/三处同改**：cn 源 + 全部对应 `*_filled.json`（+ 译名表）；修复后**成品级 GFF 复扫归零**（verify 抓不到内容对错）。

## 🔴 坑 17（2026-09-15 实锤）：审计工具自身的假阳性与假阴性
- **假阳性**：`_name_audit.py` 不区分 `Scimitar(弯刀)` 与 `Falchion(弯刃大刀)`，纯中文子串计数把 129 处正确译名当错报 → 专名一致性必须**按英文键分类**判定，且判定前先查译名表禁令（`Scimitar→弯刀` 不变、禁盲替换）。
- **假阴性（脚本从未跑通）**：`audit_residual_en.py` 两处 `print` 内嵌 ASCII 双引号截断字符串 → **SyntaxError，该审计维度从未生效**。改中文全角引号修复后首跑即抓出 Act I 57 条。
- **误报需真伪复核**：残留英文命中 ≠ 漏译——`strref=-1` 才是确定漏译；strref 有效需查官方 TLK 覆盖与内容一致性（错配 → 坑 15 处置）；超出 TLK 范围 → 确定漏译。技术串（作者署名/隐形容器/开发残留名）有意不译。
- **教训**：**审计工具本身也要验收**（`py_compile` + 首跑抽查），从未跑通过的「通过项」是盲区；审计报告发现误报必须**勘误留痕**（顶部勘误框作废错误结论），不能静默改掉。

## 🔴 坑 18（2026-09-16 实锤）：`.ncs` 编译脚本里的台词是独立缺陷面
- **现象**：GFF 层（dlg/uti/utc…）全部验收通过，但 Act I 实测仍有 105 条英文台词——它们不在任何 GFF 资源里，而在**编译后的 `.ncs` 脚本**内嵌字符串常量中（SILENT_TALK 式旁白、脚本直接 `SpeakString`）。
- **根因**：`.ncs` 是 NWScript 字节码，字符串常量直接内嵌在指令流里；**变长修改必须同步改 NCS 头里的字节码长度字段**，不是普通 GFF 回嵌。
- **正解**：
  - **审计必须覆盖 dlg + ncs 两条线**（`work/_audit_*_en.py`）；
  - ⚠️ **`SILENT_TALK` 类台词禁译**（引擎行为依赖，译了会破坏机制）；
  - 改 `.ncs` 字符串属高危操作，须实机验证后再量产。

## 🔴 坑 19（2026-10-13 实锤，~439 utc 污染）：多资源循环里共享临时文件名
- **现象**：批量处理 utc 时所有轮次写同一个临时文件；某轮异常退出后，下一轮直接读到**上轮残留**——最终 ~439 个 utc 全被写成同一只半龙人。污染期产出（10-10 晚~10-13 14:20 的存档）可能残留。
- **根因**：循环体内临时文件名固定；无"每轮强制新建/校验"防线。
- **正解**：**临时文件必须唯一名**（`tempfile` 带随机后缀，或文件名含循环索引），处理前 assert 文件是本轮刚写的；批量改 GFF 的工具一律先在干净底版上验证一轮再放量。

## 环境坑（跨机实测：macOS + Windows）

- **Git Bash 已损坏**（`dirname`/`cd` 找不到）→ 一律用 Python 绝对路径。
- **PowerShell stdout 常被吞** → 脚本结果一律 `| tee`/`Out-File` 落盘再 Read，别信回显。
- **PowerShell 内联 python 的 `%s` 会被当 cmd 变量语法拦下** → 写脚本落盘再执行，别用 `-c` 含 `%` 的代码。
- ⚠️ **`backfill.py` 启动即一次性 load 全部 `batch_*.json` / `nondlg_*_filled.json`**：回填**运行期间**才 `apply_cn` 写入的批**不会进本次成品** → 必须等回填结束再重跑一遍；终态校验务必等**最后一次**回填跑完再 `verify_struct_all`。
- ⚠️ **34MB 整包重嵌前台 120s 超时 SIGKILL** → 后台跑（`run_in_background` / `> log 2>&1 &`），约 5 分钟。
- ⚠️ **抽查成品别用"通用专名"当探针（假阳性）**：验证某批是否入包，要挑**该批独有**的字符串；用 Python `b.find(s.encode('utf-8'))` 查二进制 mod（grep 对二进制不可靠）。
- ⚠️ **`verify_struct_all.py` 的相对路径会拼到 `汉化问题/MOD/modules/` 下**：传参只给**文件名**，传 `../MOD/modules/x.mod` 会拼成双份路径 → `FileNotFoundError`。

## 坑 20–22（2026-10-17 KM 实战新增）

- **坑 20：子代理专名漂移**。多代理并行翻译同一项目，同一专名出现 4 种拼法（Cyan→凯安堡/赛安/席恩/青堡）。对策：派发前把**唯一裁定表**固化进规范（含禁用变体），主控收货后按替换对批量修正 + 全量复查；交付后再跑一轮专名一致性全扫（独立审查口径）。
- **坑 21：索引字典 dict 值内嵌表达式**。`T[i] = "...".replace(...)` 会被当**纯文本**写进译文（`.replace("<tc>","<him/her>")` 原样上屏）。apply 只警告 token 数、不查字面量污染 → 自检必须加 `'replace(' not in v`；dict 值一律纯字符串字面量。
- **坑 22：关键字批量修 json 误伤**。`if 'flea' in k` 批量修 token，连中 4 键毁 3 条无辜译文。对策：用**唯一锚点**（长短语精确片段）逐条修，修后全量 token/脏文本复查。
- **坑 23（顺带）：两把 strref 工具别混**。`fix_strref_mismatch.py`（坑15，Aielund 同 strref 复用专用）**不适用**三部曲 tri.py 流水线（按英文原文匹配，不依赖 strref 对位）；三部曲用泛化 `*_strref_fix.py`（内嵌含中文→strref=-1，防 TLK 遮蔽）。

## 坑 24–27（10-18 ncs 四轮实战）

- **坑 24：ncs 长度前缀是 2 字节大端**。单字节守卫在串长 32–126B 时被前缀低位（可打印 ASCII）干扰漏扫整常量——三部曲 421 条漏译根因。一律用 `lib/ncs_strings.py` 的 2 字节解析。
- **坑 25：终检假 0 的三种来源**。①过滤条件错（ncs rtype=1323 非 2010，用 magic 判定）；②守卫口径与真实常量形态不匹配；③**扫描对象不是当前部署产物**（旧 sha 数据复用）。门禁上线前先验证能抓到已知残留。
- **坑 26：混合常量对长度守卫免疫**。短 key 部分命中后，常量=中文+英文残段，前缀对残段失效 → 需「前邻字节 ≥0x80 的 ASCII 段」第四口径检测，key 按残段原样补丁。
- **坑 27：审查/复扫数据有时效**。落盘的 JSON/报告绑定产物 sha；产物变更后必须重扫，否则修复报告互相矛盾（10-18 审查引用 patch2 前 sha 误报「SG 仍 184」）。
